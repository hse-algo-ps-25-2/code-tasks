# Задание №9. Вариант 2. Ленточная стратегия

## Задание

Реализована модель предметной области для задач из теории расписаний. Классы `Task`, `ScheduleItem`, `AbstractSchedule`, а также сообщения в `errors.py` и шаблоны строк в `constants.py` входят в эту модель. Их не нужно изменять.

В файле `schedule.py` реализовать два метода класса `Schedule`:

- `__calculate_duration` — возвращает продолжительность кратчайшего расписания $T_{\mathrm{opt}}$;
- `__fill_schedule_for_each_executor` — заполняет расписание каждого исполнителя элементами `ScheduleItem`.

Число исполнителей задаёт конструктор.

Простой — `ScheduleItem` с задачей `None`. В строковом виде его название — `downtime`. Незанятая часть окна исполнителя записывается простоем. Исполнитель, которому не достался фрагмент ленты, простаивает всё окно длины $T_{\mathrm{opt}}$.

Конструктор уже проверяет список задач и даёт исключения из `errors.py`. Пустой список и элемент, не являющийся `Task`, дают `ScheduleArgumentError`. Метод `get_schedule_for_executor` даёт `ScheduleArgumentError`, если индекс не целый неотрицательный или не меньше числа исполнителей.

В файле `test.py` приведены примеры. Команда расширяет набор тестов, чтобы убедиться в корректности своего решения. При проверке учитываются и тесты команды, и дополнительные проверки преподавателя, которые в репозиторий не публикуются.

## По теме

Ленточная стратегия в этом задании задаётся так:

1. количество заданий произвольно;
2. каждое задание имеет свою длительность, длительности положительны;
3. задания независимы: разные исполнители могут работать одновременно;
4. прерывания разрешены;
5. число исполнителей $k$ произвольно и в ходе выполнения не меняется;
6. исполнители универсальны: каждый может выполнять любое задание;
7. производительность исполнителей и оплата их труда не учитываются;
8. нужно выполнить все задания за кратчайшее время.

Пусть $t_1, \ldots, t_n$ — длительности заданий в исходном порядке и $t_{\max} = \max t_i$. Продолжительность кратчайшего расписания

$T_{\mathrm{opt}} = \max\{t_{\max},\ (t_1 + \cdots + t_n)/k\}$.

Задания в исходном порядке составляют ленту. Её режут на фрагменты длины $T_{\mathrm{opt}}$. Фрагмент с индексом $0, 1, \ldots$ получает исполнитель с тем же индексом. Разрез может пройти внутри задания: это прерывание, и задание продолжает следующий исполнитель. В один момент времени задание выполняет один исполнитель. Последний фрагмент может быть короче $T_{\mathrm{opt}}$, а число фрагментов — меньше $k$.
