# Руководство по участию в разработке

Данный документ содержит правила разработки, форматирования кода и сдачи выполненных заданий для участников команды.

---

## 1. Порядок работы с Git и ветками

1. **Коммиты:**

* Делайте атомарные коммиты с понятными сообщениями на русском или английском языке (например,
  `feat: добавлена итеративная функция Фибоначчи`).
* Не коммитьте служебные файлы (`.venv`, `__pycache__`, `.ruff_cache`, артефакты профилирования).

---

## 2. Локальная настройка окружения

1. Убедитесь, что установлен Python 3.14+ и менеджер пакетов `uv`.

2. Запустите скрипт автоматической настройки:

```bash
./install-dev.sh
```

Скрипт установит зависимости, создаст виртуальное окружение `.venv` и активирует pre-commit хуки.

---

## 3. Требования к коду и локальная проверка

Перед отправкой кода на проверку обязательно прогоните линтер и тесты:

1. **Проверка стиля и статический анализ:**

```bash
uv run ruff check .
```

2. **Автоматическое форматирование:**

```bash
uv run ruff format .
```

3. **Запуск модульных тестов:**

```bash
uv run python -m unittest discover -s . -p "test*.py"
```

> Все проверки должны завершаться без ошибок.
---

## 4. Правила оформления Pull Request (PR)

1. **Целевая ветка (Base):**

* При открытии PR убедитесь, что в качестве **base** вы брали ветку задания `main-task-N` (например, `main-task-1`), а
  **не** `main`.

2. **Заполнение шаблона PR:**

* Заполните пред-PR чеклист.
* Приложите результаты профилирования работы функций из консоли (`@profile`).
